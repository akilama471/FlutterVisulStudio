# Phase 5 — Implementation Report

Status: **complete**

Phase 5 closes the loop from the visual canvas to a real project file. Generated Dart can now be
reviewed as a line diff and written to the project entry point after an explicit confirmation. An
existing entry point is backed up first.

The repository has no `AGENTS.md` or product roadmap, so the scope was selected explicitly by the
user and captured in `docs/phase-5-plan.md`:

> Apply generated Dart to the project safely. Write to the project entry point with a diff preview,
> explicit confirmation, and a backup of the existing file.

## Scope delivered

- **Apply to project** action in the Dart preview.
- Read of the entry point through Rust, with `null` for a missing file.
- Bounded line diff with added/removed line numbers and a large-file fallback.
- Review dialog showing the exact target, overwrite/new state, summary, and backup rule.
- Explicit **Write to project** / **Create file** confirmation and **Cancel**.
- Sibling backups: `lib/main.dart.bak`, then `.bak.1`, `.bak.2`, and so on.
- Creation of a missing entry point without a backup.
- Write result feedback with the relative target and backup path.
- Rust-side validation: active project root, `lib/` only, `.dart` only, no traversal or absolute
  paths, directory and symlink checks, and a 1 MiB cap.
- Unit tests for diffing, the dialog, the apply flow, the frontend API, and Rust file operations.
- Phase 5 badge, welcome capability, and welcome note.
- All Phase 0–4 behaviour is retained.
- No new Tauri plugin or capability entry was required.

## Non-goals

- Writing design JSON or any file other than the Dart entry point.
- Editing generated code before writing, or a general writable file editor.
- Running `flutter analyze`, `pub get`, `run`, or hot reload after writing.
- File watching, external-change detection, or reloading the preview from disk.
- Multi-file generation, cloud sync, export/import, or design sharing.
- Undoing a write from inside the application beyond restoring the backup manually.
- Drag and drop, multi-select, copy/paste, or undo/redo.

## Architecture

### Rust commands

`src-tauri/src/commands/project.rs` adds two commands registered in `lib.rs`:

```rust
#[tauri::command]
pub fn read_project_file(
    state: State<'_, ProjectState>,
    relative_path: String,
) -> Result<Option<String>, String>;

#[tauri::command]
pub fn write_project_file(
    state: State<'_, ProjectState>,
    relative_path: String,
    contents: String,
) -> Result<ProjectWriteResult, String>;

pub struct ProjectWriteResult {
    pub relative_path: String,
    pub backup_path: Option<String>,
    pub bytes: usize,
}
```

Shared validation in `resolve_file_target`:

- Reject empty paths, absolute paths, and every component that is not `Normal`.
- Require at least two components, the first exactly `lib`, and a final `.dart` file name.
- Canonicalise the parent and require it to stay inside the canonical project root.
- For existing targets, canonicalise the file, require it inside the root, and require a file (not a
  directory).
- Cap reads and writes at 1 MiB with `FILE_TOO_LARGE`.
- Return friendly errors for no project, unavailable paths, outside-project targets, and invalid
  targets.

Write order:

1. Validate the target and content size.
2. If the target exists, copy it to the next free backup name.
3. Write the generated bytes.
4. Return the normalised relative path, backup path, and byte count.

A failed backup aborts the write. If the write fails after a successful backup, the backup remains.

### Frontend

| File                                    | Responsibility                                             |
| --------------------------------------- | ---------------------------------------------------------- |
| `src/shared/lib/project.ts`             | `readProjectFile`, `writeProjectFile`, response validation |
| `src/features/dart/diff.ts`             | Bounded LCS line diff and large-file fallback              |
| `src/features/dart/ApplyDartDialog.tsx` | Review dialog, diff rendering, actions, Escape handling    |
| `src/features/dart/DartPreview.tsx`     | Apply state machine, read/write calls, result feedback     |
| `src/app/DesignSurface.tsx`             | Passes the project into the Dart preview                   |
| `src/shared/styles/global.css`          | Dialog, diff, and wrapped action styles                    |

Flow:

1. **Apply to project** sets `reading` and calls `readProjectFile(target)`.
2. A successful read opens the dialog; a failed read shows an error in the Dart header without
   opening the dialog.
3. **Write to project** sets `writing`, disables both actions, and calls `writeProjectFile`.
4. Success closes the dialog and shows `Written to <path>` plus the backup path when present.
5. Failure re-enables the dialog and shows the Rust error with `role="alert"`.
6. Escape, the backdrop, and **Cancel** close the dialog only when no write is in progress.

Target selection is `project.entryPoint ?? "lib/main.dart"`.

Diff behaviour:

- Lines are normalised from CRLF and split without a synthetic trailing empty line.
- A bounded LCS (2,000 lines each) produces `same`, `added`, and `removed` rows with line numbers.
- Larger inputs use a coarse removed-then-added diff and show `Large diff summarised`.
- The dialog shows `+n added` / `−n removed` and an `Existing file` or `New file` label.

Accessibility:

- `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and `aria-describedby`.
- Initial focus on **Cancel**.
- Escape cancels when not writing.
- The diff region is labelled and rows are exposed as table rows.
- Errors use `role="alert"`.

## Limitations and follow-ups

- The write replaces the user's entry point. The sibling backup is the only in-app recovery path, and
  backups accumulate beside the file and are visible to git and tooling.
- Generated code is a fixed standalone Material app, not a merge into the user's existing app.
- The diff is computed from the file read when the dialog opens. An external edit between the read
  and the write is captured by the backup but is not otherwise merged or detected.
- Backups are numbered without timestamps and capped at 1,000 candidates before writing fails.
- Paths are validated in Rust, but there is no virus scanning, encoding detection, or line-ending
  preservation. Files must be UTF-8 and writable.
- Only one file, the entry point, can be written; there is no file picker or multi-file output.
- The studio does not run, analyse, format, or hot-reload the project after writing.
- A failed write after a successful backup leaves the backup in place.
- The review dialog traps focus only through its content order; there is no full focus-trap loop.
- The bundle identifier `com.flutteruistudio.app` still ends in `.app`, which triggers a non-blocking
  Tauri warning and should be renamed before shipping macOS bundles.
- Installers are unsigned, so Windows SmartScreen may warn on other machines.
- Release artifacts are not committed to git; rebuild with `pnpm tauri build`.
